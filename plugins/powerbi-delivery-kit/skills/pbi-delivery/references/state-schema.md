# state.json schema (`pbi-delivery/state/1`)

One file per project at `projects/<name>/state.json`. It drives both the mockup (phase 4) and
`scripts/build-pbir.js` (phase 7). The first version is generated by `scripts/draft-state.js`
from the intake (see `intake.md`). Illustration only: `projects/finance-tracker/state.json` in the
repo where the skill was built.

## Top level

| Key | Required | Meaning |
|---|---|---|
| `$schema` | yes | `"pbi-delivery/state/1"` |
| `intake` | no | paths to `design-tokens.json` / `model-plan.json` and the `toConfirm` list (written by `draft-state.js`) |
| `project` | yes | kebab-case project name |
| `updated` | yes | ISO date of last edit |
| `dataStatus` | yes | `"sample"` or `"real"` — pages must say so in `tag` while sample |
| `designSystem` | yes | see below |
| `canvas` | no | `{ width:1920, height:1080, padding:32, gutter:24, radius:12 }` (defaults shown) |
| `shell` | no | sidebar + header; omit `sidebar` for a full-width page |
| `model` | yes | `measureTable` + `measures[]` (business definitions) |
| `pages` | yes | ordered list of pages |
| `pbiNotFeasible` | no | mockup elements that Power BI cannot render, with the chosen substitute |
| `sampleData` | no | values used for sample partitions and the mockup |

## designSystem

```json
{
  "name": "<DS brand>",
  "skill": "<client>-dashboard-design",
  "theme": ".claude/skills/<client>-dashboard-design/assets/<client>-theme.json",
  "themeName": "<ThemeBaseName>",
  "font": "<Primary>, <Fallback>, sans-serif",
  "colors": { "ink": "", "muted": "", "subtle": "", "surface": "", "border": "", "accent": "",
              "sidebar": "", "sidebarText": "", "sidebarSection": "", "onAccent": "" }
}
```
All colors come from the client DS tokens. The generator warns when one is missing and uses a
neutral placeholder.

## shell

```json
"shell": {
  "sidebar": { "width": 240, "brand": "<wordmark>", "subtitle": "<report name>", "section": "MAIN MENU",
               "items": ["Overview", "Detail", "..."] },
  "header": { "height": 72 }
}
```
The active nav item is the page's `navLabel` (default: `title`). Navigation is visual only.

## model

```json
"model": {
  "measureTable": "_Measures",
  "measures": [
    { "name": "Net Revenue", "definition": "Sum of Fact Sales[Amount] excl. returns", "format": "$#,##0" },
    { "name": "_Status Color Net Revenue", "definition": "green if ≥ target else red", "hidden": true }
  ]
}
```
`definition` is the business rule (for the user, the mockup and the model builder), not DAX.
Definitions starting with `PROPOSED` or `TBD` are not confirmed yet.

`calc` (optional, required by `build-html.js` for every measure a page uses) is the same rule in a
form the interactive HTML can compute. Keep it equivalent to the DAX — both must print the same numbers:

| calc | Equivalent DAX |
|---|---|
| `{ "agg": "count" }` | `COUNTROWS(Fact)` |
| `{ "agg": "count", "where": { "Fact X[Col]": ["G", "E"] } }` | `CALCULATE(COUNTROWS(Fact), Fact[Col] IN {...})` |
| `{ "agg": "sum" \| "avg" \| "min" \| "max" \| "distinct", "column": "Fact X[Col]", "where"? }` | `SUM` / `AVERAGE` / `MIN` / `MAX` / `DISTINCTCOUNT` |
| `{ "divide": ["A", "B"], "blankAsZero"?: true }` | `DIVIDE([A] (+ 0), [B])` |
| `{ "template": "Sobre {Partidos Con Resultado} partidos" }` | `"Sobre " & FORMAT([...], "<measure format>") & " partidos"` |
| `{ "js": "(c) => ..." }` | Anything else (rankings, counts of groups). `c.m(name, rows?)`, `c.groupBy(field, rows?)` → `[{key, rows}]`, `c.fmt(name\|format, v)`, `c.formatCode(v, code)`, `c.max/min/distinct(field, rows?)`, `c.filter(rows, {field, values})`, `c.rows` |

Empty results are `null` (= BLANK). Top-level `"locale"` (default `es-CO`) sets number/date formatting
in the HTML; it should match the model culture.
The generator checks every measure used on a page exists in the TMDL.
`model.tables` / `model.relationships` (optional) summarize `intake/model-plan.json`.

## pages

```json
{
  "id": "overview",                       // kebab-case, = mockups/<id>.html
  "title": "Overview",                    // Power BI page displayName
  "navLabel": "Overview",                 // optional
  "pbiName": "<existing page folder>",    // optional: pin to an existing PBIR page
  "mockup": "mockups/overview.html",
  "headline": { "measure": "_Headline Overview" },   // or { "text": "static insight" }
  "tag": "FY 2026 · sample data",         // right side of header
  "filters": [{ "field": "Dim Date[Year]", "values": [2026] }],
  "slicers": [                            // interactive HTML only (sidebar "FILTROS")
    { "field": "Dim Date[Date]", "type": "range", "label": "Fecha" },
    { "field": "Fact Sales[Channel]", "type": "list", "label": "Canal", "labels": { "": "Sin canal" } }
  ],
  "rows": [ { "height": 140, "items": [ ... ] }, { "height": "fill", "items": [ ... ] } ]
}
```
`slicers` are drawn by `build-html.js` only; `labels` maps raw values to display text (`""` = blank).
In the HTML, clicking a chart category cross-filters the other visuals (click again or Esc to clear).

### Layout math (same in mockup and Power BI)
- Content x = sidebar width + padding; content width W = canvas width − sidebar − 2 × padding.
- Rows start at header height + padding, separated by `gutter`. `"fill"` rows share what is left.
- Items in a row share `W − gutter × (n−1)` in proportion to `span` (default 1).
  Example: spans `1,1,1,1.6` on W=1616 → 336, 336, 336, 536.

### Item types

| type | Fields | Renders |
|---|---|---|
| `kpi` | `label`, `measure`, `reference?` (text measure), `status?` (hex-color measure), `valueStatus?` | Tile: label, big value, reference line colored by `status` |
| `kpiGroup` | `items[]` of `{label, measure, status?}`, `reference?`, `status?` | One tile with 2–4 values side by side (hero card) |
| `chart` | `visual`, `title` or `titleMeasure`, `category` (`Table[Column]`), `series[]` `{measure,label?,color?}`, `lines[]` (combo only) `{measure,label?,color?,style?}`, `sort?` `{field,direction}`, `legend?` | `columnChart`, `clusteredColumnChart`, `barChart`, `clusteredBarChart`, `lineChart`, `areaChart`, `stackedAreaChart`, `lineClusteredColumnComboChart` (lines share the column axis) |
| ↳ chart options | `axisType` (`Categorical` shows every category, `Scalar`), `categoryWidth`, `axisFontSize`, `yMin`/`yMax` (value-axis start/end), `legendWidth` (room kept for the legend next to a measure title) | Same meaning in Power BI and HTML |
| `table` | `title`/`titleMeasure`, `columns[]` `{field}` or `{measure,label?}`, `sort?` | `tableEx`, grow-to-fit |
| `text` | `text`, `size?`, `color?`, `bold?`, `align?` | Static textbox |

Rules:
- Chart colors: main series = DS accent, comparison = DS secondary, others neutral; status colors
  only through `status` measures. Max 2 saturated series unless the DS defines a category palette.
- Sort month axes by the month column (its `sortByColumn` in the model handles calendar order).
- A KPI without `reference` violates the "every number has a reference" rule — add one or justify it.

## Ownership
Pages listed here are rebuilt entirely by the generator on every run. For hand-authored pages
(slicer-heavy, maps, bookmarks), keep them out of `pages` and author them with powerbi-report-cli.
